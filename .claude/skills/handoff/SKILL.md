# 주고받기

강사와 학습자는 각자의 PC에서 이 저장소를 쓴다. 서로에게 전할 것은 `records/`의 파일로 쓰고 git으로 보낸다. 파일 모양과 누가 어느 파일을 쓰는지는 [records-format.md](records-format.md)에 있다. 기록을 쓰기 전에 반드시 읽는다.

## 먼저: 이 PC의 사용자가 누구인지

저장소 루트의 `.jwstudy-role` 파일을 읽는다. 내용은 `learner` 또는 `instructor` 한 단어다. 파일이 없으면 사용자에게 강사인지 학습자인지 묻고 만든다. 이 파일은 git에 올라가지 않는다.

역할에 맞지 않는 명령은 실행하지 않는다. 학습자가 피드백을 쓰거나 강사가 제출을 대신 쓰면 기록의 의미가 없어진다.

## 명령

### 받기 (둘 다)

1. `git pull`로 최신 상태를 받는다.
2. 상대 폴더에서 지난번 받은 뒤 바뀐 파일을 찾는다: `git log --since` 또는 방금 pull이 가져온 커밋의 변경 파일.
3. 새로 온 것만 요약한다.
   - 학습자에게: 새 피드백(잘한 것, 다시 볼 것), 통과 여부, 질문에 달린 답.
   - 강사에게: 새 제출(주차, 요약, 설명 못 하는 부분), 새 질문, 새 프롬프트 기록.
4. 새로 온 것이 없으면 없다고만 말한다.

### 제출 (학습자)

1. 이번 주가 몇 주차인지 확인한다. `records/settings.json`의 시작일로 계산하고, 애매하면 묻는다.
2. 학습자에게 세 가지를 묻는다. 하나씩 묻고, 대신 써 주지 않는다.
   - 결과물이 어디 있는지 (`homework/` 아래 경로 또는 배포 주소)
   - 이번 주에 배운 것을 내 말로 두세 줄
   - 아직 설명하지 못하는 부분
3. "내 말로"가 코드 붙여 넣기이거나 문서 문장을 옮긴 것이면 다시 써 달라고 한다. 강사가 평가하는 것은 이 설명이다.
4. `records/learner/week-NN.json`의 `submission`에 쓴다. 학습자의 문장은 고치지 않는다.
5. 아래 "보내기"를 한다.

### 질문 (학습자)

20분 넘게 막힌 것만 올린다. 먼저 AI에게 물어봤는지 확인하고, 아니라면 지금 같이 풀어 본다.

1. 세 가지를 받는다: 하려던 것, 막힌 곳, AI가 한 답과 그래도 안 풀린 이유.
2. `records/learner/week-NN.json`의 `questions`에 다음 번호(`q1`, `q2` …)로 추가한다.
3. "보내기"를 한다.

### 피드백 (강사)

1. 대상 주차의 학습자 제출을 읽어 보여 준다.
2. 강사에게 두 가지를 받는다: 잘 설명한 것 하나, 다시 볼 것 하나. 여러 개를 말하면 하나씩으로 줄이게 돕는다. 한 번에 고칠 것이 많으면 학습자는 어느 것도 고치지 못한다.
3. 세션 기록(막힌 개념, 다음 주 조정)이 있으면 함께 받는다.
4. 통과 여부는 강사가 말한 그대로만 적는다. 말하지 않았으면 묻는다.
5. `records/instructor/week-NN.json`에 쓰고 "보내기"를 한다.

### 답변 (강사)

1. 답이 달리지 않은 질문을 보여 준다.
2. 강사의 답을 받는다. 답이 정답을 그대로 알려 주는 내용이면, 학습자가 직접 찾을 수 있게 "다음에 해 볼 것 하나"로 바꿀지 강사에게 한 번 묻는다. 결정은 강사가 한다.
3. `records/instructor/week-NN.json`의 `answers`에 질문 id로 쓰고 "보내기"를 한다.

## 보내기

1. 내 폴더만 스테이징한다. 학습자는 `git add records/learner homework`, 강사는 `git add records/instructor records/settings.json`.
2. `git diff --cached --name-only`로 내 폴더의 파일만 들어 있는지 확인한다. 다른 파일이 섞였으면 빼고 사용자에게 알린다.
3. 커밋한다. 메시지는 `기록(3주차): 학습자 제출`, `기록(3주차): 강사 피드백`처럼 주차와 내용을 적는다. 이 PC에 커밋 방법을 정한 전역 규칙이 있으면 그 방법을 따른다.
4. 무엇을 보낼지 한 줄로 보여 주고, 사용자가 좋다고 하면 `git pull --rebase` 뒤 `git push` 한다. 확인 없이 push 하지 않는다.
5. push가 실패하면 원인을 알려 주고 멈춘다. 강제 push는 하지 않는다.

## 말투

기록은 상대가 읽는 글이다. 두 사람이 쓴 문장은 그대로 옮기고, AI가 덧붙이는 요약은 사실만 짧게 쓴다. 평가하는 말("훌륭합니다", "부족합니다")을 AI가 보태지 않는다.
